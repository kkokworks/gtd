# 프로젝트 굴리기 (루트 세션)

이 세션이 Mindwtr 프로젝트(업무 묶음) 하나를 맡습니다. 묶음 안의 이슈별 다음 행동을 보고, 워커가 할 수 있는 일은 nod 에 맡기고, 이 묶음의 결정만 받아 전합니다. 묶음마다 루트 세션을 하나씩 두면 여러 묶음이 동시에 돕니다. nod 를 다루는 법(맡기기·결정·결과 내보내기)은 nod 스킬을 따르고, 이 파일은 묶음과 이슈를 nod 에 잇는 부분만 다룹니다.

## 시작

1. 맡을 프로젝트를 정합니다. 사용자가 이름을 주지 않았으면 `mindwtr_list_projects` 로 진행 중인 것을 보여 주고 고르게 합니다.
2. 그 프로젝트의 열린 할 일(`inbox`·`next`·`waiting`)을 읽고 이슈 키 목록을 만듭니다. 키는 제목·설명의 이슈 번호입니다. 이슈가 없는 일은 프로젝트 이름을 공백 없이 써서 키로 삼습니다.
3. [scan.md](../../scan.md) 의 "끝난 일 정리"로 이 할 일들의 실제 상태를 맞춥니다.
4. `nod --issue <키,…>` 로 이미 열린 결정이 있는지 보고, 있으면 먼저 전합니다.

끝: 키 목록과 이슈별 상태(다음 행동, 맡긴 nod 작업, 열린 결정)를 표로 보여 줬습니다.

## 맡길 일 고르기

워커는 레포 안의 코드·문서 일만 할 수 있습니다. 네트워크가 막혀 있고 MCP 도구는 쓸 때마다 결정으로 올라옵니다. 사람에게 묻기·요청·재촉·리뷰는 이 세션이 사용자와 함께 합니다.

1. 항목마다 워커 일인지 사람 일인지 나눕니다. 워커 일은 이슈를 읽어 무엇을, 어느 레포에서, 무엇이 되면 끝인지 정합니다.
2. 워커 일끼리의 관계는 이슈가 아니라 고칠 파일로 판단합니다. 이슈가 달라도 같은 파일(DB 마이그레이션, 공통 라우터·메뉴 등)을 고치면 이어진 일입니다. 관계에 따라 아래 표대로 나눕니다.

   | 관계 | 맡기는 법 |
   |---|---|
   | 서로 독립 | 이슈마다 `nod add`. 동시에 돌고 워크트리가 따로 생깁니다 |
   | 한 줄로 이어짐(A → B), B 는 A 의 결과만 필요 | `--after` 로 잇습니다. 같은 레포면 B 는 A 의 브랜치에서 시작합니다 |
   | 한 줄로 이어짐, B 에 A 의 맥락이 통째로 필요하거나 둘 다 작음 | 작업 하나로 묶습니다. 두 개까지만 묶고, 더 길면 `--after` 로 잇습니다. 맥락이 쌓이면 워커 성능이 떨어집니다 |
   | 두 갈래가 합쳐짐(A, B → C) | 같은 레포면 한 작업으로 묶습니다. 레포가 다르면 `--after A,B` |

3. 나눈 계획(작업, 이슈, 순서, 사람 일)을 표로 보여 주고 사용자 확인을 받습니다.

끝: 사용자가 계획을 확인했습니다.

## 맡기기와 지켜보기

1. 작업마다 nod 스킬의 "일 맡기기"대로 `nod add … --issue <이슈 키>` 를 합니다. 작업 하나에 이슈 둘을 묶었으면 앞 이슈의 키를 주고, 뒤 이슈는 지시에 적습니다.
2. 연결 표시는 [SOURCE.md](SOURCE.md) 의 "맡기기"대로 남깁니다. 작업 하나에 이슈 둘을 묶었으면 두 이슈의 항목 모두 설명 첫 줄을 `nod #<작업>` 으로 둡니다. 작업이 성공하면 알림이 둘 다 닫습니다.
3. Monitor 로 `nod watch --issue <키,…>` 를 겁니다. 이 묶음의 결정만 오고, 이 묶음의 워커가 모두 멈추면 끝납니다. 결정은 nod 스킬대로 전합니다.
4. 묶음에 이슈가 새로 들어오면 키 목록을 고쳐 watch 를 다시 겁니다.
